# 공개 요청 반영 — 2026-11-06

사용자가 제출 발표자료의 평가표·배점 논의를 제거하고, 작성한 코드를 GitHub에 올려 공개 데모와 연결하며 저장소를 공개하도록 명시 요청했다. 에이전트는 발표자료를7장으로 정리하고 공개 비식별 데모·소스 링크를 연결했다. 실제 원본·실거래 상세는 계속 로컬에 분리한다. 역사적 비공개 승인과 현재 공개 승인을 구분한다. 클래스룸 제출은 별도이며 이번 공개로 대신하지 않는다.

아래는 이전 단계의 작업 기록이다.

# 에이전트 작업 기록

평가용 요약이다. 비밀번호·토큰·원문 대화·공개 집행기록 전문은 저장하지 않는다. 기계적 검증과 사람의 판단을 구분한다.

## 주요 요청과 범위 결정

1. 사용자: 공공기관 업무추진비 공개기록을 참고해 출장자·현지인이 식당을 찾는 MVP를 요청했다. 에이전트: 출처 조사, 수집·정규화, 식당 후보와 주소 대조, 코드·테스트를 수행했다.
2. 사용자: 자체 지도보다 목록 중심을 선택했고, 주소 클릭 시 식당명을 빼고 주소만 네이버지도에서 검색하도록 고쳤다. 에이전트: Python 생성 HTML과 지역 필터의 JavaScript 링크를 함께 변경하고 실제 새 탭을 확인했다.
3. 사용자: 평점은 제외하고 이용기록 수 내림차순을 선택했다. 에이전트: 수치 정렬·동률 처리·미확인 수를 0으로 만들지 않는 검사를 추가했다. 기록 수를 실제 방문 인증이나 지역 인기순위로 표현하지 않는다.
4. 사용자: 이용기록 수 클릭 팝업을 승인했고 화면 확인 후 괜찮다고 답했다. 에이전트: 날짜·확인 기관/부서·목적·원문 링크만 표시하고, 건수와 상세 행 수를 비교했다.
5. 사용자: 광주 전역으로 자료 범위를 넓히도록 요청했다. 에이전트: 5개 구의 제한 표본을 조사하고 동명이점·주소·선정 조건·목적문장을 검토해 12곳·160건의 비공개 로컬 결과를 만들었다. 5개 구청을 전부 수집한 것은 아니다.
6. 사용자: 평가 기준을 참고해 GitHub에 우선 비공개 업로드하도록 승인했다. 에이전트: 평가표를 다시 읽고 자체 소스·문서·합성 예제만 업로드 대상으로 분리했다. 공개 전환과 실제 기록 재배포는 승인 범위에 포함하지 않는다.

## 막힌 곳과 복구

| 문제 | 처리와 한계 |
| --- | --- |
| 흩어진 XLS/XLSX/HWPX, 날짜·헤더·부서 표기 차이 | 날짜와 헤더 파서를 테스트 우선으로 구현했다. 파싱 실패·기간 밖 자료를 따로 남겼고 누락을 0으로 꾸미지 않았다. |
| 같은 이름의 부서와 반복 게시 자료 | 기관별 namespace와 고유키로 묶고 출처를 유지했다. 참석인원 충돌은 보류했으며 확정 방문 수라고 부르지 않았다. |
| 동명이점과 원문에 없는 사업장 주소 | 독립 주소 근거와 거래 상호를 대조했고 모호한 후보는 제외했다. 영수증 수준 사업장 동일성이나 현재 영업 인증은 못 한다. |
| 동구·남구·북구청 접근 제한 | robots 제한을 확인하고 수집을 멈췄다. 우회하지 않았으며 자료 공백은 남겼다. 해당 구 식당은 다른 기관 기록과 식당 주소로 분류했다. |
| 조사 에이전트의 사용량 제한 | 완료/부분 결과를 구분해 보존하고 재개 후 부모 에이전트가 근거를 직접 다시 읽었다. 실패한 작업을 성공한 것처럼 보고하지 않았다. |
| 팝업 닫기 직후 테스트가 상태 복귀를 너무 일찍 검사 | native close 이벤트를 기다리도록 검증 조건을 수정했다. 앱의 정상 비동기 동작을 결함으로 오인해 코드를 바꾸지 않았다. |
| 상세 JSON의 건수만 맞아도 오래된 자료일 수 있음 | 원본/입력 해시, 정확한 선택키, 모든 식당 그룹, 허용 공식 URL과 승인된 출력 해시를 별도 결합했다. 목적문장 수동 검토는 여전히 필요하다. |
| Python 최적화에서 일부 assert 검사가 사라짐 | 알려진 Minor로 명시했다. 로컬 실제자료 빌드는 PYTHONOPTIMIZE=0으로만 검증했으며 자동 운영·임의 입력 안전성을 보증하지 않는다. |
| 실데이터 제외 시 새 복제본의 UI를 실행할 수 없음 | 실제 기록과 명확히 구분한 합성 3곳·6건 예제를 추가했다. 합성 실행 결과를 실제 식당 확보나 원본 재현으로 포장하지 않는다. |

## 사람이 확인한 것과 아직 남은 것

- 사용자 결정: 목록 중심, 주소 전용 지도 검색, 평점 제외, 건수 정렬, 상세 팝업, 광주 확대, 현재 비공개 업로드.
- 사용자 확인: 기존 팝업 화면을 확인하고 승인했다. 이 확인을 모든 브라우저·모바일 기종의 사용자 테스트로 확대 해석하지 않는다.
- 에이전트 검증: 자동 테스트·원본 셀/해시 대조·주소 근거 읽기·브라우저 조작·독립 코드 검토. 자세한 범위와 한계는 docs/verification.md에 있다.
- 미실시/미확정: 현장 방문, 사용자 3–5명 사용성 검증, 지역/기관 전수 수집, 재배포 권리 정리, 현재 영업 보증.
- 별도 남은 제출: 실제 동작 영상 또는 수업 중 라이브 시연, 구현 결과 슬라이드의 별도 클래스룸 제출. 이번 GitHub 업로드가 이를 완료한 것은 아니다.
