# Project rules

- Work on a feature branch, not main/master. Commit and push only after the user approves the browser preview and the commit.
- Keep the repository private until the user explicitly approves public visibility. Never enable Pages or change visibility automatically.
- The root .gitignore is a default-deny allowlist. Never force-add raw documents, transaction files, location records, HTML evidence, credentials, or the output directory.
- Preserve actual records; do not fabricate restaurants, responses, coordinates, opening status, or counts. Synthetic test fixtures are not real evidence and must never enter exports.
- Distinguish public accessibility from reuse permission. Unresolved data stays local; source-code licensing does not license external data.
- Tests: .venv/bin/python -m unittest -v. Test failures must be reported. Do not collect network data when merely running tests.
- pipeline.py downloads and normalizes; export_data.py exports local verified inputs. Map properties must not expose departments, amounts, counts, or personal information.
- Current user-facing MVP is a regional restaurant list, not an embedded map. export_list.py emits output/restaurant_list.html with name/address and Naver Map search links. Coordinate requirements belong to the older map pipeline, not this list renderer. Keep the old map as a local historical artifact; do not expand data collection or change selection rules just to render the list.
- Latest approved list fields: id/name/address/region/record_count. Show aggregate public-use records as 이용기록 N건, not certified visits; order by numeric record_count descending, then name/id for ties. Preserve this order after region filtering. Never substitute missing counts with zero. Ratings are excluded. Keep the observation period in internal documentation for a later app-description section rather than repeating it on restaurant rows.
- Latest approved drill-down: counts open a native dialog with manually reviewed date/organization/department/purpose/source_url, latest first. Organizations come only from explicit source headings, never inferred from current hosting domain or spender role; unknown remains null/기관명 미확인. Keep the main list minimal. Exclude amounts, attendees, staff identities, contact details, file paths and raw audit objects even from embedded JSON. popup_review.private.json gates the selected records by source hash and explicit transaction keys. New source text needs another manual privacy review; regex masking is defense-in-depth, not comprehensive PII detection. All generated record details remain private/local.
- Report partial coverage, uncertain transaction-to-place identity, duplicate candidates, and unparsed files honestly.
- Latest explicitly approved data expansion: the local list now covers restaurants in all five Gwangju districts using vetted regional/Seogu/Gwangsan samples. The private workspace is ../gwangju-wide-2026, outside this Git repository; its approval.private.json gates the latest12-place/160-record build. The old build_list_pilot.private.py/popup_review.private.json are historical6-place inputs and explicit source-heading evidence, not the latest regeneration recipe. Use the reviewed build command with PYTHONOPTIMIZE=0; do not use -O because some private input/hash checks still use assert. Preserve the old map and baseline; no raw/processed/evidence upload, commit, or public hosting is approved.
