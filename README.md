# 기록으로 찾는 지역 식당 목록

공공기관 업무추진비 공개기록을 정리해, 광고·협찬 대신 실제 이용 기록을 참고하며 지역 식당을 찾도록 돕는 MVP다. 출장자와 현지인 모두를 대상으로 한다. 시작 지역은 전남광주통합특별시이며, 실시간 서비스가 아니라 분기 갱신을 목표로 한다.

## 현재 상태

현재 MVP는 자체 지도 시각화가 아닌 식당 목록이다. 지역 선택 → 상호·주소 목록 → 주소 클릭 시 네이버지도 검색 결과를 새 탭으로 연다. 이 저장소는 데이터 수집·정규화·목록 출력 코드와 테스트를 관리한다. 아직 개발 중이며 비공개로 관리한다. 공개 전 이용조건과 비밀정보를 다시 점검한다.

최신 목록은 광주 5개 구의 식당 12곳·공개 이용기록 160건이다. 기존 본청 표본 96첨부에 서구·광산구 각60첨부를 추가했고, 신규 대상기간 원문1601행에서 장소·선정 조건·팝업 문구를 검토했다. 과거 4점 지도와 6곳·74건 목록은 보존했다. 전 지역·전 기관 완전수집, 현재 영업, 실제 방문·맛·가성비 보증을 뜻하지 않는다. 영수증에 주소나 사업자 식별자가 없는 경우 장소 연결에는 한계가 있다.

## Quick Start — 실자료 없는 합성 화면 재현

이 저장소에는 자체 코드·문서·합성 예제만 포함한다. **실제 식당 12곳·160건의 거래 자료와 HTML은 포함하지 않는다.** 아래 명령은 실제 수집이나 실제 식당 검색이 아니라 합성 식당 3곳·합성 기록 6건으로 UI를 확인한다.

Python 3.14 / Linux·WSL 기준이다. 화면 생성에는 표준 라이브러리만 필요하며 API 키, 패키지 설치, 외부 자료 수집이 필요 없다. 비공개 저장소이므로 GitHub 저장소 접근 권한이 있는 계정으로 받는다.

    git clone https://github.com/urikkiri0919/local-table-map.git
    cd local-table-map
    python3 export_list.py --input examples/synthetic-restaurants.csv --records examples/synthetic-records.json --output output/demo.html

브라우저에서 `output/demo.html`을 직접 연다. 생성 결과의 `restaurants`는 3이다. 모든 식당명에 [합성]을 붙였고 주소·기관·집행목적도 가짜임을 명시했다. example.com 링크는 예시 도메인이며 실제 원문이 아니다. 자세한 구분은 examples/README.md를 참고한다.

확인할 동작:

1. 전체 3곳의 합성 기록 수가 3/2/1 내림차순으로 표시된다.
2. 북구 선택 시 합성 식당 1곳, 남구 선택 시 준비 중, 전체 선택 시 다시 3곳이 표시된다.
3. 이용기록 버튼을 누르면 대응하는 합성 상세 3/2/1건이 최신 날짜순으로 열리고 닫기·Esc로 닫힌다.
4. 주소 링크의 검색어에는 주소만 포함된다. 합성 주소는 실제 식당 위치를 찾는 입력이 아니다.

합성 예제의 식당·주소·기관·2000년 날짜는 실제 공개자료가 아니며 연구기간/선정 조건을 충족한 실제 후보라고 주장하지 않는다. 실제 12곳·160건 결과는 기존 로컬 연구 환경에서만 열 수 있다. 새 복제본으로 실제 자료를 그대로 재현하거나 공개 서비스로 쓰는 배포판은 아니다.

## 사용자 흐름과 범위

- 흩어진 업무추진비 자료를 원본·정규화 거래·목록용 자료로 구분한다.
- 지역별 식당 후보의 상호명·주소를 목록에서 본다. 주소를 누르면 식당명을 제외한 전체 주소만 네이버지도에서 검색한다. 특정 업체 상세페이지로의 확정 연결은 아니다.
- 식당별 공개 이용기록 수를 표시하고 숫자가 많은 순으로 정렬한다. 동률은 식당명 순이다. 이는 수집자료의 기록 수이며 실제 방문 확정 횟수나 지역 전체 인기순위가 아니다. 기본 목록에는 기관명·부서를 표시하지 않는다. 이용건수를 눌렀을 때만 별도 팝업에서 날짜·확인된 출처 기관/부서·집행목적·원문 게시물 링크를 보여준다. 지출금액은 표시하지 않는다.
- 평점은 도입하지 않는다. 식당별 집계기간도 표시하지 않으며, 기간 안내는 나중에 앱 설명란에서 다루기로 했다. 실제 집계기간은 내부 데이터와 이 문서에 유지한다.
- 지자체·경찰·소방을 수집 대상군으로 계획했지만, 현재 결과는 본청 및 서구·광산구 부서/동 자료의 제한 표본이다. 동구·남구·북구청 직접 수집은 robots 제한으로 원문을 확보하지 못했고 무집행0으로 해석하지 않는다. 해당 구의 식당은 다른 기관의 공개기록과 별도의 식당 주소 근거로 확인했다. 이번 확대에서 경찰·소방 자료를 추가 수집하지 않았다.
- 예약·리뷰·결제·실시간 수집·광고에 따른 노출 변경은 하지 않는다.

## 요구 환경

Python 3.14 / WSL에서 검증했다. 목록 HTML은 별도 서버·라이브러리·API 키 없이 브라우저로 열며, 목록·지역 필터·기록 팝업은 오프라인에서도 동작한다. 네이버지도와 원문 링크를 열 때 인터넷이 필요하다. 예전 지도 미리보기는 Leaflet CDN 및 OpenStreetMap 타일에 인터넷 연결이 필요하다.

## 설치 및 테스트

프로젝트 폴더에서 실행한다.

    python3 -m venv .venv
    .venv/bin/python -m pip install -r requirements.lock.txt
    .venv/bin/python -m unittest -v

테스트는 네트워크 요청 없이 실행되며, 합성 테스트 입력은 실제 데이터 출력과 분리한다. 기존 목록/파이프라인 26개와 정규화·승인 경계 18개를 함께 실행하는 구성이다. wide_data.py와 test_wide_data.py는 기존 비공개 통합 작업의 데이터 없는 범용 코드·합성 테스트를 그대로 포함했다. 원본 수집/승인 파일과 실제 기록은 옮기지 않았다.

Python 최적화(-O)는 사용하지 않는다. 실제자료 승인 빌드의 일부 assert 검사가 최적화에서 제거되는 알려진 제한이 있으므로 PYTHONOPTIMIZE=0인 일반 실행을 사용한다. 이 소스의 합성 테스트 통과가 임의 실자료의 개인정보·재배포 권리를 보증하지 않는다.

## 데이터 처리 실행

실제 다운로드 전에 해당 기관과 위치정보 출처의 이용조건을 확인한다. 아래 명령은 단순 테스트가 아니라 외부 게시판에 요청하고 자료를 로컬에 저장한다.

    .venv/bin/python pipeline.py collect --limit 8
    .venv/bin/python pipeline.py extract

- 사용일 기준 2026-01-01~2026-09-30을 대상으로 한다. 늦게 게시된 자료도 실제 사용일로 판정한다.
- XLS/XLSX/HWPX를 처리한다. PDF/HWP, 미게시·파싱 실패는 별도 보완 대상이다.
- 공개 자료 전체가 아니라 명시한 수의 첨부를 고른 표본 수집이다. 부서별·월별 완전성은 보장하지 않는다.
- raw/, manifest.json, transactions_unique.json 등은 로컬에 생기며 Git에서는 제외한다.

## 목록형 결과물 (현재 MVP)

기존 로컬 검증 자료로 다음 명령을 실행한다.

    .venv/bin/python export_list.py

결과: output/restaurant_list.html. 브라우저에서 파일을 직접 연다. 현재 목록은 서구6·광산구3·동구1·남구1·북구1, 총12곳/160건이다. 새로 신청담한우·규슈 상무점·또바기초밥·광산나주곰탕·남구 덕림산방·북구 영발원을 포함했다. 새6곳은 각각 독립 공개 본문2개와 정확한 거래상호를 대조한 연구 후보다. 해송·청담 등 알려진 동명이점은 보류를 유지한다. 자료가 없는 지역은 식당이 없다고 단정하지 않고 준비 중으로 안내한다. 내장 지도·마커·좌표는 사용하지 않는다.

입력은 output/list_ready.csv가 있으면 우선 사용하며, 없을 때만 이전 지도 파일럿의 output/map_ready.csv를 사용한다. 목록 허용 필드는 id/name/address/region/record_count이며 좌표 열은 무시한다. 최신 record_count는 기관별 출처부서 단위를 구분하고 선정 조건을 통과한 고유 record_key 수로 검산했다. 예전 transaction_key와 원본 연결도 별도 보존한다. 수가 없는 예전 CSV는 0건으로 꾸미지 않고 기록 수 확인 중으로 표시하며 목록 끝에 배치한다. 다른 검증 CSV는 --input 경로, 출력은 --output 경로로 지정한다. 원본 파일·개인정보·금액·내부 감사 객체는 HTML에 포함하지 않는다. 새로운 자료는 먼저 상호·주소·근거·선정 조건을 검토해야 하며, 목록 생성기 자체가 데이터의 진위를 검증하는 것은 아니다.

최신 검토·통합 작업영역은 ../gwangju-wide-2026/이며 Git 저장소 밖의 비공개 로컬 자료다. 원본·검토 입력과 approval.private.json이 모두 유지됐을 때 프로젝트 폴더에서 다음 명령으로 검토된 staged 결과를 재검증·재생성한다.

    PYTHONOPTIMIZE=0 PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B ../gwangju-wide-2026/build_wide.private.py render

출력은 ../gwangju-wide-2026/output/이며, 브라우저와 실제 건수/해시 검증 후에만 이 프로젝트의 output/에 반영한다. 새 자료를 검토하지 않고 approval 파일을 자동 갱신하지 않는다. 단순 export_list.py 성공은 새 원본 검토 완료를 뜻하지 않는다. 예전 build_list_pilot.private.py는 보관된6곳용이므로 최신 목록 재생성에 사용하지 않는다. 과거 입력은 ../gwangju-wide-2026/baseline/에 보존했다. 기존4점 지도 산출물은 변경하지 않았으므로 output/summary.json은 과거 지도 기준이며, 최신 목록 수량은 output/list_summary.private.json을 확인한다.

운영 제약1건: 일부 원본/승인 해시 검사가 assert 기반이어서 Python 최적화(-O 또는 PYTHONOPTIMIZE) 실행은 지원하지 않는다. 위 명령처럼 PYTHONOPTIMIZE=0인 일반 실행만 사용한다. 명시적 예외로 바꾸는 후속 보완은 남아 있으나 이미 검증한12곳/160건 정적 결과에는 영향을 주지 않는다.

새로 복제한 저장소에는 실제 검증 CSV와 실데이터가 포함되지 않는다. 먼저 위 Quick Start의 합성 예제로 UI를 재현한다. 실제 자료는 허용 필드에 맞는 별도 검토·승인된 입력이 필요하며 기존 수집 명령만 실행한다고 현재 12곳·160건이 재현되는 것은 아니다. 파일을 내려받았다는 이유만으로 재배포 가능하다고 간주하지 않는다.

### 이용기록 팝업

현재 식당12곳에 연결된160건의 상세 기록을 최신 날짜부터 보여준다. 닫기 버튼·Esc·배경 클릭으로 닫으면 기존 지역과 정렬을 유지하며 원래 이용건수 버튼으로 초점이 돌아온다. 모바일에서는 팝업 안의 기록만 스크롤한다.

기본 목록과 연결된 검토 완료 자료 output/list_records.private.json이 있으면 HTML에 date/organization/department/purpose/source_url 다섯 필드만 포함한다. 금액·대상인원·사용자 직함/성명·파일/시트/행·원문 객체는 넣지 않는다. 기관명은 공식 게시제목·게시판 표제의 명시 근거가 있는 경우만 표시하고 없는 기록은 기관명 미확인과 출처 부서를 표시한다. 새 표기는 광역 소속 명칭을 소급하지 않는 서구청/광산구청이며, 현재 도메인이나 집행자 직함으로 과거 법적 소속을 추정하지 않는다. 서구의 원문 링크는 원사이트가 제공한 통합 게시목록이며 특정 영수증 한 행으로 직접 연결되는 것은 아니다.

현재 자료는 새 작업영역 approval.private.json의 수동 검토 대상 record_key 집합과 원본/입력23개·CSV·상세 해시가 일치할 때만 비공개 빌드에서 다시 만든다. 식당별 그룹 전체 존재·건수·정확한 공식 manifest URL도 확인한다. 예전 popup_review.private.json은 과거6곳의 검토 및7개 원본 파일의 명시 기관명 근거로 보존한다. 전화·연락처·명시적인 이름 라벨 마스킹은 보조장치이며, 임의의 개인정보를 모두 찾는 기능이 아니다. 원본 변경·기록 추가 시 별도 검토가 필요하다. 조회화면에서 상세기록을 숨겨도 HTML 내부에는 해당 허용 필드가 포함되므로 외부 게시하지 않는다.

다른 검증 데이터에는 --records 경로로 대응하는 상세 JSON을 명시한다. 원시 audit JSON을 그대로 넘기지 않는다. 건수와 상세 행 수가 다르면 생성이 중단되며, 상세자료 없이 만든 파일은 준비 중으로 안내한다. 원문 보기에는 인터넷 연결이 필요하다.

## 기존 지도 파일럿 재현 (보관용)

기존 로컬 연구 폴더에는 검증 입력이 남아 있으므로 다음 명령으로 재생성할 수 있다.

    .venv/bin/python export_data.py

새로 복제한 저장소에는 외부자료 재이용 권리 미확정으로 원본·거래·places_verified.json이 포함되지 않는다. 먼저 위 수집·가공을 실행하고, 검증된 위치 입력을 작업 폴더의 places_verified.json에 별도로 준비해야 실제 마커가 나온다. 위치 입력이 없으면 빈 지도만 생성되며, 식당 자료가 있다고 주장하지 않는다.

places_verified.json은 객체 배열이다. 각 객체는 name, address, longitude, latitude, region, geo_source, place_verified, ambiguous, is_restaurant 필드를 가진다. 증거 URL과 정확한 좌표·지점이 확인된 경우에만 place_verified=true를 사용한다. 입력 예시는 실제 식당 데이터가 아닌 test_pipeline.py의 명시적 테스트 픽스처를 참고한다.

출력:

- output/map_preview.html — 로컬 지도. 브라우저로 직접 연다.
- output/map_ready.csv — 상호·주소·경위도·지역.
- output/map_ready.geojson — [경도, 위도] Point.
- output/selection_audit.private.json — 내부 근거 추적.
- output/review_queue.private.csv — 판단 보류 자료.

전체 output/을 GitHub나 웹서버에 올리지 않는다. 코드를 처음 설치한 사람에게 실데이터 4점 데모가 자동 재현되는 공개 배포판은 아직 아니다.

## 검증과 알려진 제한

검증 결과는 docs/verification.md에 정리했다. 현재 테스트는 날짜·기간, 지출 분류, 직함/부서 구분, 중복키, 위치 검증 조건, 좌표 순서와 지도 필드 노출을 검사한다.

- 중복키가 같은 5쌍 중 일부는 참석인원이 달라 확정 중복 판정이 아니다. 원본과 duplicates.json을 보존하며 현재 4개 지도 후보에는 영향이 없음을 확인했다.
- 회의·간담회 지출 기록을 명시적 식사·대면 방문으로 단정하지 않는다.
- 일부 원본은 자동 추출되지 않았고, 보류 자료가 남아 있다. 누락을 지출 0으로 취급하지 않는다.
- 데이터 재배포 권리와 위치 출처의 이용조건, 거래-업소 동일성, 현재 영업 여부는 추가 확인이 필요하다.

## 사람과 에이전트

에이전트는 수집·정리·테스트·위치 출처 대조를 돕는다. 사람은 범위와 선정기준, 권리와 개인정보, 결과의 실제 쓸모를 판단한다. 자동 처리 결과를 사람의 실제 확인·사용자 테스트 결과로 포장하지 않는다.

## 공개 계획과 라이선스

현재 사용자 승인 범위는 기존 GitHub 저장소에 자체 소스·문서·합성 예제를 PRIVATE로 업로드하는 것이다. 공개 전환·Pages 배포·실데이터 업로드·클래스룸 구현물 제출은 이번 범위가 아니다. README, LICENSE, .gitignore, .env.example과 재현 가능한 합성 예제를 갖추더라도 **비공개 상태는 소스 공개 가산점 조건을 충족하지 않는다.** 공개 전환에는 별도 사용자 승인과 전체 커밋 이력의 비밀정보 검토가 필요하다.

클래스룸 구현물 평가 기준과 기말 소스 공개 조건은 docs/assessment-checklist.md, 주요 요청·사람의 확인·문제 복구는 docs/agent-worklog.md에 정리했다. GitHub 업로드를 별도 슬라이드 제출이나 실제 동작 데모 수행으로 대신하지 않는다.

원본·가공 데이터·지도 증거·.venv·비밀정보는 기본 차단하는 .gitignore 허용목록을 사용한다. git add -f로 우회하지 않는다. MIT LICENSE는 자체 코드와 자체 문서에만 적용하며 외부자료 사용권을 부여하지 않는다.
